# Тестовое задание: Менеджер задач

## Описание

Реализовать SPA - менеджер задач для команды на Vue 3 + TypeScript + Pinia + Vite по Feature-Sliced Design.

## Время

Задание по времени может занять 2-3 рабочих дня. Это не хакатон на 2 часа - ожидаем зрелый код. Если за 2 дня не получается успеть - это тоже информация.

## Требования

### Общее

- Можно использовать любую UI-библиотеку по желанию (целевая на реальном проекте - Element Plus)
- Требования к стилям: не делать слабый контраст между передним и задним фоном. Все остальное - на усмотрение кандидата

### Что нужно сделать

1. Создать страницу с задачами:
   - Реализовать в виде канбана, где столбцы - это статусы задач, а карточки - это задачи. В карточках указать название, статус, приоритет, на кого назначена, и дату создания задачи. Для вывода статуса предусмотреть вывод человеко-читаемого названия.
   - Кнопка "Создать задачу": Должна вызывать диалоговое окно с формой создания задачи:
     - Форма со всеми полями, кроме id, comments и createdAt
     - Статус задачи по умолчанию - "todo" (в форме на создание не выводится)
     - При успешном создании задачи -> навигация на /tasks/:id
     - Кнопка "Отмена" - закрывает диалоговое окно на текущей странице
     - Валидация полей должна быть реализована с проверкой по схеме:
       - Название - обязательное поле, минимум 3 символа, максимум 200 символов
       - Описание - необязательное поле, максимум 2000 символов
       - Приоритет - обязательно поле, выбор из 3 вариантов ('Низкий', 'Средний', 'Высокий')
     - Валидация на дубликат - по названию (проверять, есть ли название в списке задач)
       -  Для проверки дубликатов название формы должна иметь доступ к списку задач     
          через Pinia store. Проверить можно так: store.tasks.some(t => t.title ===     
          data.title)
   - Клонирование задачи (полное клонирование задачи с комментариями, меняется только id)
   - Удаление задачи (перед удалением - подтверждение от пользователя с возможностью подтвердить/отменить)
   - Фильтрация задач: 
     - Компонент должен осуществлять фильтрацию по названию, статусу (множественный выбор) и приоритету (множественный выбор). Фильтры могут быть применены одновременно.
     - Сброс фильтров - ко кнопке "Сбросить фильтры"
     - К соответствующим полям формы фильтра применить проверки:
       - Название - минимум 3 символа, максимум 200
2. Создать страницу с детальной информацией о задаче:
   - При переходе на /tasks/:id - выводить детальную информацию о задаче, но, данные нужно имитировать (получать расширенные данные, где будут еще и комментарии к задаче)
   - Реализовать режим чтения данных и редактирования:
     - По-умолчанию - режим чтения (вывод всех полей карточки, кроме id) + кнопка "Редактировать" - открывает форму в диалоговом окне со всеми полями, кроме id, comments, и createdAt. 
     - Кнопка "Сохранить" - сохраняет данные и закрывает диалоговое окно.
     - Валидацию полей - как в пункте 1.
     - На странице реализовать кнопку "Назад" - возвращает на страницу с задачами.
   - Если задача не найдена - редирект на /tasks
   - На странице с детальной информацией реализовать возможность CRUD'а для комментариев (создать, редактировать, удалить)
3. TypeScript строго типизирован - нет ни одного any
4. Yup валидация - обязательные поля + ограничения на значение
5. Loading & Error state - не скрывать от пользователя. При имитации загрузки данных - нужно имитировать лоадер. Также, все ошибки, которые возникают в процессе валидации - показывать пользователю (каким образом - на усмотрение разработчика)
6. FSD - соблюдение потока импортов
7. Hash-based маршрутизация (createWebHashHistory)
8. Состояние приложения должно храниться в Pinia (смысл - хранить объекты превью карточек задач и полный объект детальной карточки с полседующим изменением его данных)

### Что не нужно сделать

1. Бекенд (используем моки)
2. Сложные стили, минимальные CSS достаточно. Акцент больше на архитектуру решений. Ничего страшного, если решения будут не идеальными
3. Unit тесты (если есть желание показать, что умеете писать тесты - будет бонус, но не требуется)

## Как сдавать

Приложить ссылку на репозиторий с решением (любой открытый репозиторий). Или архивом - на усмотрение кандидата

## Дополнительные (бонусные) фичи - если успел

- Toast уведомления при сохранении/ошибке
- Unit-тесты, минимум 1 тест на проверку значений
- Использовать DTO-прослойку данных при получении от API (mapper)
- Расширить комментарии временем (Тип comments?: { text: string; createdAt: string }[] ) и добавить на детальную страницу сортировку по комментариям (время asc/desc)
- Дать возможность перетаскивать карточки между столбцами:
    - При перетаскивании карточки в другой столбец - менять статус задачи, только, после оставления комментария, который будет добавляться в текущую задачу, которая перетаскивается (при расширении комментария временем - добавлять в начало списка)
- Адаптивность стилей для мобильных устройств

// shared/api/task-api.ts

export interface Task {
  id: string
  title: string
  description?: string
  status: 'todo' | 'in_progress' | 'done'
  assignee: string          // email
  priority: 'low' | 'medium' | 'high'
  createdAt: string         // ISO date string
}

// + описать TaskFull, где будет comments?: string[]

export interface TaskFilters {
  title?: Task['title']
  status?: [] // дописать тип
  priority?: [] // дописать тип
}

export const taskApi = {
  // GET /tasks?status=...
  getAll(filters: TaskFilters = {}): Promise<Task[]> {
    const delay = () => new Promise(r => setTimeout(r, 2000))
    return delay().then(() => mockTasks.filter(t => !filters.status || t.status === filters.status)) // дописать приведение TaskFull к Task
  },

  // GET /tasks/:id
  getById(id: string): Promise<TaskFull | null> {
    const delay = () => new Promise(r => setTimeout(r, 2000))
    return delay().then(() => mockTasks.find(t => t.id === id) ?? null)
  },

  // POST /tasks
  create(data: Omit<TaskFull, 'id' | 'createdAt'| 'comments'>): Promise<TaskFull> {
    const delay = () => new Promise(r => setTimeout(r, 2000))
    return delay().then(() => {
      const task: TaskFull = {
        ...data,
        id: crypto.randomUUID(),
        createdAt: new Date().toISOString(),
      }
      mockTasks.push(task)
      return task
    })
  },

  // PUT /tasks/:id
  update(id: string, data: Partial<Omit<TaskFull, 'id' | 'createdAt'| 'comments'>>): Promise<TaskFull> {
    const delay = () => new Promise(r => setTimeout(r, 300))
    return delay().then(() => {
      const idx = mockTasks.findIndex(t => t.id === id)
      if (idx === -1) throw new Error('Task not found')
      mockTasks[idx] = { ...mockTasks[idx], ...data }
      return mockTasks[idx]
    })
  },
}

## Роуты

```
// app/router/index.ts

import { createRouter, createWebHashHistory } from 'vue-router'

const router = createRouter({
  history: createWebHashHistory(),
  routes: [
    {
      path: '/',
      redirect: '/tasks',
    },
    {
      path: '/tasks',
      name: 'task-list',
      component: () => import('@/pages/task-list/index.vue'),
    },
    {
      path: '/tasks/:id',
      name: 'task-card',
      component: () => import('@/pages/task-card/index.vue'),
      props: true,
    },
  ],
})

export default router
```
